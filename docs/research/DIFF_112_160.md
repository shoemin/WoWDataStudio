# 1.12.1 vs "1.60": every client-side difference, measured

Research note, 2026-10-20. It is the basis for a later in-app catalog of "portable updates": pieces of the modern 1.60
Classic client that could be moved into our 1.12 client one at a time. Maps and terrain are already covered in
`MAP_SURVEY_160.md`, so this note only points to that survey for them. Read `CASC_INVESTIGATION.md` for how the CASC
storage is read, and `MAP_CONVERSION_DESIGN.md` for the converter plan.

The survey was read-only. Only `G:\WoW Clients and Patches\Clients\` was read, and nothing there was written. Nothing
was launched, there was no network access, and no listfile was used. No repo file other than this one was written.

How the claims are marked:

* **MEASURED**: a probe read the real files and counted. Numbers in tables are measured unless marked otherwise.
* **FORMAT KNOWLEDGE**: public format facts (wowdev-wiki style) that were not checked here.
* **INFERRED**: derived from measured data by a stated rule.

Sources:

* 1.60 = `BattleNet snapshot 2026-10-20\_classic_beta_` (1.60.1.70450, `WowB.exe`).
* Era = `_classic_era_` (1.15.9.70003). Retail = `_retail_` (12.1.5.70448). Both were used only for names and as
  references (content keys).
* 1.12 = `1.12.1.5875 - WoW Client` (`WoW.exe`, `Data\*.MPQ`).

---

## Summary: the big picture

1. **1.60 is a modern Retail-engine client that carries Classic content. It is not a remastered 1.12.** Of its 1,245,465
   files (enUS records, 118 GB):
   * **985,923 (79%, 89 GB) are byte-identical to Retail 12.1.5** (same FileDataID, same content key);
   * 75,182 (6%) are identical to Era 1.15.9;
   * 74,154 are Era files with changed content;
   * 66,933 are Retail FileDataIDs with other content;
   * **43,273 (3.5%, 6.5 GB) exist only in 1.60.**

   The executable grew from 4.8 MB to 86.5 MB. It uses D3D11/D3D12, Lua 5.1, Slug font rendering and FMOD Studio. It
   has 1,170 DB2 tables (1.12 has 154 DBCs) and about 300 Lua `C_` API namespaces. All MEASURED.
2. **Graphics and lighting are mostly engine features. A smaller part is data that 1.12 could use.**
   * Engine (needs client code):
     * new lighting tables (`LightData` with 5,910 rows, `LightDataGlobalVolumeFog` with 11,200 rows only in 1.60,
       `ZoneLight`/`ZoneLightPoint`, light shafts, world shadows, `SSAOSettings`, `TerrainColorGradingRamp`);
     * procedural sky;
     * PBR/FFT water (`LiquidType` 57 rows against 5 in 1.12);
     * about 950 compiled shader containers (`GXSH`);
     * render options: SSAO/ASSAO, ray-traced shadows, cascaded soft shadows, MSAA/FXAA/FFX anti-aliasing, render
       scale with resampling, variable-rate shading, volumetric fog, sun shafts, outlines.
   * Data that is portable with a converter: sky colours and fog distances (`Light`/`LightParams`/`LightData` →
     `LightIntBand`/`LightFloatBand`), skybox models, water and lava textures for the four 1.12 liquid kinds, weather
     textures, spell and particle models.
3. **HD textures.** 96,404 textures have a second, high-resolution twin (usually 4x the width). The twins add 67.4 GB on
   top of the 6.0 GB standard set. 35,199 twins are named; nearest-neighbour inference names 42,642 more, and that
   inference is 99.9% correct on named files. By area, the largest groups are:

   | Area | Twins |
   |---|---|
   | icons | about 21,300 |
   | items | about 24,400 |
   | guild emblems | 6,086 |
   | characters | 4,700 |
   | creatures | 3,300 |
   | dungeon/WMO textures | 3,800 |
   | ground textures | 2,300 |

   They are plain BLP files, so they are portable once downscaled or once the 1.12 engine accepts large textures.
4. **UI.** 1.60 ships the **Retail ("Mainline") UI**, not a Classic UI: MEASURED, the `Classic\` family files are not in
   its root. It has 160 Blizzard addons, plus 167 "camelot" override files (camelot is 1.60's game type).
   * It calls 2,716 functions in 219 `C_` namespaces and 923 global API functions that 1.12's exe does not have.
   * It uses mixins in 1,402 files and 60 XML element types that 1.12 lacks.
   * **No substantive 1.60 addon runs on the 1.12 Lua API.** Only 7 trivial stubs pass the check.

   What is portable is art (134,284 interface textures, named) and text (27,389 GlobalStrings against 5,470).
   Functionality needs client code, or a rewrite against the 1.12 API.
5. **Assets.** Of the 79,733 files in 1.12:

   | Status in 1.60 | Files | Share |
   |---|---|---|
   | byte-identical | 24,001 | 30% |
   | changed, but identical to Era (format updates, for example `.wav` → `.ogg`) | 7,826 | 10% |
   | changed in 1.60 itself | 30,453 | 38% |
   | gone (mostly old WMO groups of replaced landmarks) | 1,535 | 2% |
   | not findable by name (7,122 md5-named minimaps, 7,538 baked NPC textures, old UI code paths) | 15,916 | 20% |

   Most of the "changed" files did not change visually:
   * a 600-file pixel comparison found 93% of the same-size textures only re-encoded, 3.3% lightly edited and 3.7%
     repainted;
   * every model was only re-saved from M2 v256 to v272/v274.

   **The real new content is in the 1.1 million Retail-shared and 1.60-only files:**
   * HD character models (10-25 MB each, against 2-6 MB in 1.12);
   * new creatures (`CreatureModelData` 1,171 rows against 430; `ModelFileData` 121,131 rows);
   * about 245,000 sound files;
   * new spell visuals (`SpellVisualEffectName` 2,732 rows against 775);
   * new maps (see the map survey).
6. **What needs client code (the decomp project):**
   * the modern lighting and fog model, procedural sky, PBR/FFT water, the shader system and render features;
   * modern M2 features (external `.skin`/`.anim`/`.bone`/`.skel` files, v272+ chunks) if models are not converted
     back;
   * the character customization system (`ChrCustomization*`, which replaces 1.12's `CharSections`);
   * the UI framework (`C_` API, mixins, animation groups, mask textures, atlases);
   * Slug fonts;
   * zone lights, weather/particulate volumes and sound emitters.

   Everything that stays within 1.12's feature set is data and can go through converters: sky colours, skyboxes, water
   textures, models after an M2 downgrade, textures after a downscale, sounds after OGG decoding, DB2 rows after DB2→DBC.

**Naming coverage without a listfile (MEASURED).** 207,367 of the 1,245,465 1.60 files are named (16.6%):

| Origin | Named |
|---|---|
| Era-identical | 85% |
| changed Era files | 58% |
| Retail-shared | 9.8% |
| 1.60-only | 3.4% |

Section 1.3 shows which method named how many. Everything else is classified by content type from its first bytes.

## 0. Method and probes

Probe folder: `<a scratch folder, not in the repo>`.
It is a C# console app on `app\WoWData.Core\bin\Release\net8.0\WoWData.Core.dll` (`CascStorage`, `ClientData`,
`BlpFile`), plus a few Python scripts run with `-I`. Build with `dotnet build -c Release -o out3`. The results are in
`results\`.

| Mode / script | What it does | Load |
|---|---|---|
| `inv` (`Inventory.cs`) | every 1.60 FileDataID: state, size, presence and content-key equality in Era, wowf, Retail; high-res twin (root opened twice, `PreferHighResTextures` false/true); name → `inventory.tsv`, `inventory_report.txt` | root, encoding and index only, 11 s |
| `heads 8 1` (`Heads.cs`) | content type from the first decoded bytes (partial read: index → archive offset → BLTE header → first chunk partly inflated). Every local file of origin A/B/E plus **1 in 8 of the Retail-shared files (C/D), extrapolated x8** → `heads_8_1.tsv` | 318,870 files, 2.28 GB raw, 384 s |
| `cmp112` (`Cmp112.cs`) | every 1.12 listfile file: FDID by name hash (plus `.wav`→`.ogg`, `.dbc`→`DBFilesClient\*.db2`), **MD5 of the 1.12 bytes against the 1.60 and Era content keys** (the content key is the MD5 of the decoded file, so 1.60 files need no reading), 1.60 header of changed BLP/M2/WMO → `cmp112.tsv`, `cmp112_report.txt` | 6.0 GB of 1.12 read once, 70 s |
| `ui [--dump]` (`Ui.cs`, `UiDiscover.cs`, `Wdc5.cs`) | names interface files from `ManifestInterfaceData.db2`; finds UI code by hashing TOC / XML `Script`/`Include` / `[Family]`/`[Game]` paths, recursively; Lua API, events, XML tags; GlobalStrings → `ui_report.txt`, `ui_files160.tsv`, `ui_files112.tsv`, `ui_api_*.txt`, `ui_events_new.txt`, dumps in `ui160\`, `ui112\` | 12 s |
| `db` (`Db.cs`) | headers of all 1,170 1.60 DB2s and 945 Era DB2s (partial reads), 154 1.12 DBC headers, DBCache.bin counts per table → `db_report.txt`, `db_tables.tsv` | 10 s |
| `gfx dbnames / twins / blpdiff 600 / naming` (`Gfx.cs`) | path strings of every DB2 string table hashed into names; twin areas (nearest named FDID, leave-one-out accuracy) and twin size ratio (**sample 1/97**); pixel diff of changed same-size BLPs (**random sample of 600**); naming coverage | |
| `exe_strings.py`, `ui_port.py`, `heads_an.py`, `area_an.py`, `ui_an.py` | exe string scan (graphics identifiers, API markers); per-addon UI portability; heads extrapolation; named-area table | |
| `casc_probe\p6_exe_dbmeta.py _classic_beta_ WowB.exe` | DB2 meta table of the 1.60 exe → `casc_probe\dbmeta_classic_beta.json` (1,170 tables) | |

Origin codes used below (MEASURED, by FileDataID and content key):

* **A**: same content as Era.
* **B**: Era has the FDID but the content changed.
* **C**: not in Era, byte-identical to Retail.
* **D**: Retail has the FDID with other content.
* **E**: only in 1.60.

### 2.4 Water (MEASURED strings and files)

* What its string table holds:
  * the classic sets: `XTextures\river\lake_a.%d`, `ocean\ocean_h.%d`, `lava\lava.%d`, `slime\slime.%d`,
    `river\fast_a.%d`;
  * **procedural textures** (`proceduralRiverDepthTex`, `proceduralOceanDepthTex`, `proceduralWmoWaterTex`);
  * **PBR water**: "PBRWater - Generic - Lake/Ocean", "PBRWater - SkyElfLand - Lake/River",
