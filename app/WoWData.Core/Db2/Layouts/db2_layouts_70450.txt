# WoW Data Studio: column names for DB2 tables of the "1.60" Classic beta client (1.60.1.70450, wow_classic_beta).
# Experimental and read-only: used by the DB2 reader (WoWData.Core.Db2.Db2Layouts.ForBuild(70450) / Load) for the
# tables a 1.60 -> 1.12 map conversion needs, and (M1 of docs\research\OPEN_OTHER_VERSIONS_DESIGN.md) the tables
# Browse needs when the 1.60 client is opened read only: creature, item, game object and spell effect displays and
# their files. Every other table opens with raw columns (col_N).
#
# Same format as Dbc\Layouts\dbc_layouts_5875.txt (one [Table] section, keys, then one line per column), with these
# differences:
#   * one line per FLATTENED column of the DB2 table (an array field of N elements is N columns: Name[N]);
#   * the record ID and the parent ID (relationship map) are not columns, except where the file keeps the ID inside
#     the record (WMOAreaTable);
#   * "layout-hash:" is the header layout hash the names were measured on: a file with another hash keeps col_N;
#   * storage words are informational: the real types (8/16/32/64-bit, signed, float, string) come from the client's
#     own field table in WowB.exe (Db2Catalog). "string" and "float" must agree with it; "int" = signed, "uint" =
#     unsigned or not measured;
#   * DB2 strings are one language (enUS here), so there is no "loc".
#   * col_N: N is the flattened column index (Db2Table.Columns), as the reader names unknown columns.
#
# Evidence (MEASURED, docs\research\CASC_INVESTIGATION.md and the probe in the scratch folder db2\probe):
#   * value matching on shared IDs with the same table of 1.12.1 (5875), 2.4.3 (8606) and 3.3.5a (12340), read with
#     their verified DBC layouts, and with WoD 6.2.3 and Era 1.15.9 raw columns; numbers compared as 32-bit values,
#     floats within 0.1%, strings as text (case-insensitive). "x/y" = equal rows / shared rows where either side is
#     not 0 or empty;
#   * links: the share of non-zero values (and not -1) that are IDs of the linked 1.60 table;
#   * FileDataID columns: the files they name were read from the local CASC storage (their magic);
#   * chains through the 1.12 tables: a 1.12 path (model, skin, icon, item model or texture name) hashed into the
#     Classic Era root gives a FileDataID (FileDataIDs are shared between the flavors), compared with the 1.60 value
#     (directly, or through ModelFileData / TextureFileData); sizes of the linked BLP textures;
#   * the 1.60 terrain itself (MH2O instances of every map with tiles, 285,312 instances) and the 1.60 map survey
#     (docs\research\MAP_SURVEY_160.md, per-chunk 1.12 liquid kinds against 1.60 liquid type IDs).
# A name without "~" has such evidence (normally >= 95% value equality, or a fully resolving link plus a value
# match). "~Name" is a best guess from the values (shown as not verified). No community definition file was used.

@build 70450 1.60.1

# ---------------------------------------------------------------------------------------------- named values

@enum InstanceType
  0 = Open world
  1 = Dungeon
  2 = Raid
  3 = Battleground

@enum LiquidKind
  0 = Water
  1 = Ocean
  2 = Magma
  3 = Slime

@enum MapType
  1 = Map with terrain tiles
  2 = WMO-only map
  3 = No WDT

@enum LiquidVertexFormat
  0 = Height + depth (5 bytes per vertex)
  1 = Height + texture coordinates (8 bytes)
  2 = Depth only (1 byte)
  3 = Height + texture coordinates + depth (9 bytes)

@enum ComponentSection
  0 = Arm upper
  1 = Arm lower
  2 = Hand
  3 = Torso upper
  4 = Torso lower
  5 = Leg upper
  6 = Leg lower
  7 = Foot
