# WoW Data Studio: the DBC layouts of the World of Warcraft 1.12.1 client (build 5875).
#
# One [Table] section per DBFilesClient\<Table>.dbc. The keys of a section:
#   category:     where the table is listed in the editor
#   about:        what the table controls in the game, in plain words
#   server:       client            only the game reads it
#                 file              the world server (VMaNGOS mangosd) reads its own copy (Server\data\5875\dbc)
#                 db <table>        the server reads the same data from that SQL table instead (edit it there)
#   server-note:  extra advice about the server
#   label:        the column that names a row in links (default: the first named text column)
#   evidence:     where the layout comes from
# Then one line per column, in file order:
#   Name[N]  [storage] [semantic] [-> LinkedTable] [=> server thing] [| hint]
#   storage:  int  uint  float  string  loc (8 languages + a flags field = 9 fields)  byte  ushort
#   semantic: id  bool  enum(Name)  flags(Name)  flags  icon  texture  model  path
#   Name[3] makes Name1, Name2, Name3. A "~" before the name: the meaning is a best guess (shown as not verified).
#   col_N: an unknown column, shown as stored.
#
# Evidence used for every table (see docs\ARCHITECTURE.md, "DBC editor"):
#   * the client itself: the record reader of each table in our decompile of WoW.exe (WoWDecomp\work\out66: the
#     <Table>Rec__Read functions and the <Table>Rec structs) gives the number of fields, the record size, which fields
#     are strings (the reader adds the string block's address to them), the 1- and 2-byte fields and many field names
#     with the client code that reads them;
#   * the server: the format strings and structures of the VMaNGOS DBC loader (read for facts only, no code taken)
#     give the types (f = decimal number) and names of the columns the server reads; the enum names below follow the
#     server's constant names;
#   * the files: every layout is checked against the 1.12.1 file (fields, record size, string offsets, value ranges);
#     the tests repeat these checks for all 154 tables.
#
# A column counts as verified (named) when the client code reads it, or the server reads it, or its public 1.12 name is
# confirmed by the file (its links resolve, its values fit the meaning). Otherwise it is "~Name" (a best guess) or col_N.
